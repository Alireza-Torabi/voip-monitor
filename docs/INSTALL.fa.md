# وضعیت نصب و روش برنامه‌ریزی‌شده

**وضعیت:** در مرحلهٔ نخست فقط شالودهٔ مخزن آماده است. هنوز برنامهٔ قابل نصب، تصویر Docker، راه‌انداز اولیه یا استقرار تولیدی پشتیبانی‌شده وجود ندارد. این مخزن را به PBX متصل نکنید.

## معماری و سازگاری

سامانهٔ پایش روی سرور یا ماشین مجازی جدا از PBX اجرا خواهد شد. هدف اولیه Asterisk و سامانه‌های مبتنی بر FreePBX است؛ سازگاری با Asterisk 13.x باید آزمایش شود. فهرست میزبان‌های پشتیبانی‌شده هنوز آزمایش و تأیید نشده است.

## پیش‌نیازهای نیازمند بررسی

Node.js 24 LTS برای توسعه پیشنهاد شده است. برای استقرار نهایی، Docker Engine و افزونهٔ Docker Compose پشتیبانی‌شده لازم خواهند بود. حداقل پردازنده، حافظه و فضای دیسک هنوز اندازه‌گیری نشده‌اند.

## روند مورد انتظار برای مدیر سامانه

۱. مخزن عمومی را دریافت کند.
۲. محل پایدار داده را بیرون از مخزن انتخاب کند.
۳. دسترسی فقط‌خواندنی AMI و قواعد دیوارهٔ آتش را برای میزبان پایش آماده کند.
۴. در صورت نیاز، دسترسی محدود SSH را برای سنجه‌های سیستم و خواندن گزارش‌ها آماده کند.
۵. پس از آماده‌شدن سرویس‌ها، استقرار Compose را اجرا کند.
۶. از طریق HTTPS مدیر نخست را بسازد، PBX را اضافه کند، اتصال و کشف فقط‌خواندنی را بررسی کند و سپس پایش را آغاز کند.

در این نسخه فرمان نصب وجود ندارد، چون سرویس اجرایی هنوز ساخته نشده است.

## داده و بازیابی

مسیر پیشنهادی داخل کانتینر `/data` است؛ پایگاه داده در `/data/monitor.sqlite3` و کلید اصلی جداگانه در `/data/secrets/master.key` خواهد بود. این موارد باید بیرون از Git باشند. پشتیبان‌گیری از پایگاه داده و کلید باید هماهنگ انجام شود؛ بدون کلید، بازیابی اطلاعات رمزگذاری‌شده ممکن است ناممکن باشد. روش آزموده‌شدهٔ بازیابی، ارتقا، بازگشت نسخه، بررسی سلامت و حذف نصب پس از پیاده‌سازی نوشته می‌شود.
