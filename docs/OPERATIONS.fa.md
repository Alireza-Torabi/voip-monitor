# عملیات

**وضعیت:** سرور و رابط توسعهٔ محلی اجرا می‌شوند، پایگاه دادهٔ SQLite وجود دارد، اما هنوز سرویس پایش یا روش کامل پشتیبان‌گیری و بازیابی وجود ندارد.

بررسی‌های کنونی را از ریشهٔ مخزن اجرا کنید:

</div>

```sh
python3 scripts/check_foundation.py
python3 scripts/check_licenses.py
npm run lint
npm run typecheck
npm run test
npm run build
git status --short --branch
git check-ignore .local/DEPLOYMENT_CONTEXT.md
```

<div dir="rtl">

این بررسی‌ها وجود فایل‌های عمومی، الگوی محیطی بی‌خطر و نادیده‌گرفتن مسیرهای خصوصی را کنترل می‌کنند. جایگزین بازبینی دستی فایل‌های آمادهٔ ثبت در Git یا ابزار کامل کشف اطلاعات محرمانه نیستند.

پایگاه داده در مسیر تنظیم‌شدهٔ `APP_DATABASE_PATH` نگهداری می‌شود؛ مسیر پیش‌فرض کانتینر `/data/monitor.sqlite3` است. کلید اصلی آینده به‌صورت جداگانه نگهداری خواهد شد. نسخهٔ پشتیبان آینده باید پایگاه داده و فایل‌های جانبی آن و در صورت وجود داده‌های رمزگذاری‌شده، کلید اصلی را حفظ کند و بازیابی را آزمایش کند. راهنمای کامل استقرار، ارتقا، بازگشت نسخه و حذف نصب پس از ساخت سرویس نوشته خواهد شد.

</div>

<div dir="rtl">

در فاز ۲ وظیفهٔ ۳، برنامه فایل SQLite را در مسیر اعتبارسنجی‌شدهٔ `APP_DATABASE_PATH` می‌سازد و مهاجرت‌ها را پیش از شروع HTTP اجرا می‌کند. شکست پایگاه داده یا مهاجرت، شروع برنامه را متوقف می‌کند. `GET /health` زنده بودن فرایند را نشان می‌دهد؛ `GET /ready` آماده بودن برنامه و پایگاه داده را بررسی می‌کند و هنگام اختلال کد 503 می‌دهد. نبودن یا قطع بودن PBX روی آمادگی برنامه اثر ندارد. نسخهٔ پشتیبان آینده باید پایگاه داده و فایل‌های جانبی مرتبط را به‌صورت سازگار حفظ کند؛ دادهٔ محرمانهٔ رمزگذاری‌شده در آینده به کلید اصلی جداگانه نیز نیاز دارد. پشتیبان‌گیری و بازیابی هنوز پیاده‌سازی و آزمایش نشده‌اند.

</div>
