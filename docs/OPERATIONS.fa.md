# عملیات

**وضعیت:** سرور و رابط توسعهٔ محلی، راه‌اندازی احرازشدهٔ PBX، نگهداری رمزگذاری‌شدهٔ گذرواژهٔ AMI، چرخهٔ اجرای ارائه‌دهنده، آزمایش احرازشدهٔ اتصال، رویدادهای نرمال‌شدهٔ AMI، Snapshot/Reconciliation معتبر کانال‌ها و State Engine داخلی و قطعی Channel/Call را دارند. State Engine هنوز از طریق REST/WebSocket منتشر نمی‌شود؛ استقرار تولیدی و روش آزموده‌شدهٔ پشتیبان‌گیری و بازیابی نیز هنوز وجود ندارند.

بررسی‌های کنونی را از ریشهٔ مخزن اجرا کنید:

</div>

```sh
python3 scripts/check_foundation.py
python3 scripts/check_licenses.py
npm run lint
npm run typecheck
npm run test
npm run build
git status --short --branch
git check-ignore .local/DEPLOYMENT_CONTEXT.md
```

<div dir="rtl">

این بررسی‌ها وجود فایل‌های عمومی، الگوی محیطی بی‌خطر و نادیده‌گرفتن مسیرهای خصوصی را کنترل می‌کنند. جایگزین بازبینی دستی فایل‌های آمادهٔ ثبت در Git یا ابزار کامل کشف اطلاعات محرمانه نیستند.

پایگاه داده در مسیر تنظیم‌شدهٔ `APP_DATABASE_PATH` نگهداری می‌شود؛ مسیر پیش‌فرض کانتینر `/data/monitor.sqlite3` است. کلید اصلی در `<APP_SECRET_DIR>/master.key` جدا از پایگاه داده، در پوشهٔ مالک‌دار با مجوز 0700 و فایل با مجوز 0600 نگهداری می‌شود. کلید گمشده در حضور رکوردهای رمزگذاری‌شده دوباره ساخته نمی‌شود و شروع برنامه شکست می‌خورد. بازیابی آینده به پایگاه داده، کلید اصلی متناظر و پیکربندی زمان اجرا در صورت نیاز وابسته است. نسخهٔ پشتیبان باید پایگاه داده و فایل‌های جانبی مرتبط را به‌صورت سازگار و کلید اصلی را با کنترل دسترسی جداگانه در صورت امکان حفظ کند. پایگاه داده بدون کلید درست ممکن است اطلاعات محرمانه را برای همیشه غیرقابل‌بازیابی کند؛ کلید به‌تنهایی رکوردهای پایگاه داده را بازسازی نمی‌کند. راهنمای کامل استقرار، ارتقا، بازگشت نسخه و حذف نصب پس از ساخت سرویس نوشته خواهد شد.


رمزگذاری اطلاعات محرمانهٔ PBX با `AES-256-GCM` و نسخهٔ پاکت و کلید ۱ انجام می‌شود. هر بار از nonce تصادفی تازه استفاده می‌شود و دادهٔ احرازشده شناسهٔ PBX، نام اطلاعات محرمانه و هر دو نسخه را به متن رمزگذاری‌شده پیوند می‌دهد. متن آشکار هنگام استفاده کوتاه‌مدت در حافظهٔ سرور وجود دارد و JavaScript پاک‌سازی قطعی آن را تضمین نمی‌کند. چرخش کلید هنوز پیاده‌سازی نشده است.
</div>

<div dir="rtl">

از فاز ۲ وظیفهٔ ۴، برنامه فایل SQLite را در مسیر اعتبارسنجی‌شدهٔ `APP_DATABASE_PATH` می‌سازد و مهاجرت‌ها را پیش از شروع HTTP اجرا می‌کند. شکست پایگاه داده یا مهاجرت، شروع برنامه را متوقف می‌کند. `GET /health` زنده بودن فرایند را نشان می‌دهد؛ `GET /ready` آماده بودن پایگاه داده و فایل کلید متناظر را بررسی می‌کند و هنگام اختلال کد 503 می‌دهد. نبودن یا قطع بودن PBX روی آمادگی برنامه اثر ندارد. نسخهٔ پشتیبان آینده باید پایگاه داده و فایل‌های جانبی مرتبط را به‌صورت سازگار حفظ کند؛ دادهٔ محرمانهٔ رمزگذاری‌شده به کلید اصلی جداگانه نیز نیاز دارد. پشتیبان‌گیری، بازیابی و چرخش کلید هنوز پیاده‌سازی و آزمایش نشده‌اند.

## راه‌اندازی مدیر نخست

پس از راه‌اندازی با پایگاه دادهٔ تازه، فایل `<APP_SECRET_DIR>/bootstrap-admin.token` را فقط با دسترسی محلی مورد اعتماد و با هویت مالک برنامه بخوانید. فایل مجوز 0600 و پوشهٔ آن مجوز 0700 دارد. آن را در گزارش، تیکت، تاریخچهٔ فرمان یا Git کپی نکنید. صفحهٔ مرورگر اکنون وجود دارد؛ یک کلاینت API هم‌مبدأ HTTPS نیز می‌تواند `username`، `password` و `bootstrapToken` را به `POST /setup/admin` بفرستد. بعد از پاسخ 201، با `POST /auth/login` وارد شوید. خروج با `POST /auth/logout` نشست را باطل می‌کند. `GET /setup/status` فقط وضعیت نیاز به مدیر را نشان می‌دهد. وضعیت راه‌اندازی به `SETUP_IN_PROGRESS` می‌رود و با ثبت نخستین PBX به `PBX_CONFIGURED_UNVERIFIED` می‌رسد؛ هنوز کامل نیست. پس از ثبت مدیر، توکن حذف می‌شود؛ اگر حذف شکست بخورد، پایگاه داده ادعای دوباره را رد می‌کند و راه‌اندازی بعدی حذف را دوباره امتحان می‌کند. بازیابی خودکار مدیر وجود ندارد و گذرواژهٔ گم‌شده به فرایند بازیابی جداگانه نیاز دارد.

نشست‌ها انقضای قطعی ۱۲ ساعته دارند. در تولید، کوکی Secure و Origin هم‌مبدأ HTTPS لازم است و پراکسی باید Host را کنترل کند. شمارنده‌های تلاش برای هر IP سوکت و کل برنامه در حافظهٔ فرایند هستند و با راه‌اندازی مجدد پاک می‌شوند؛ سربرگ‌های IP ارسال‌شده از کلاینت معتبر نیستند. استقرار چندنمونه‌ای به محدودکنندهٔ مشترک نیاز خواهد داشت. `/ready` پیش و پس از ساخت مدیر، در صورت سلامت ذخیره‌سازی، آماده است؛ `/health` اطلاعات حساب را نشان نمی‌دهد.

## راه‌اندازی محلی PBX

پس از ورود، از فرم دوزبانه برای افزودن پروفایل Asterisk / FreePBX استفاده کنید. در توسعه فقط دادهٔ ساختگی وارد کنید. فرم نام نمایشی، میزبان یا IP برای AMI، درگاه AMI (پیشنهاد 5038)، نام کاربری و گذرواژهٔ تازهٔ AMI را ثبت می‌کند. گذرواژه فقط قابل‌نوشتن است؛ پروفایل ذخیره‌شده تنها وضعیت «گذرواژه ثبت شده» را نشان می‌دهد. خالی گذاشتن فیلد هنگام ویرایش، گذرواژهٔ قبلی را نگه می‌دارد؛ مقدار غیرخالی آن را جایگزین می‌کند و دکمهٔ حذف گذرواژه آن را صریحاً پاک می‌کند. فعال/غیرفعال‌کردن خواستهٔ محلی پروفایل را عوض می‌کند؛ در حالت پیش‌فرضِ شبکهٔ غیرفعال هیچ اتصالی باز نمی‌شود، اما در حالت صریح `plain_tcp` چرخهٔ اجرای همان ارائه‌دهنده آغاز یا متوقف می‌شود. حذف پروفایل ابتدا اجرای آن را متوقف و سپس پروفایل و رکوردهای رمزگذاری‌شدهٔ وابسته را از SQLite این برنامه پاک می‌کند.

مسیرهای هم‌مبدأ `GET/POST /api/pbx-instances` و `GET/PATCH/DELETE /api/pbx-instances/:id` همگی نشست مدیر می‌خواهند و تغییرها بررسی Origin وظیفهٔ ۵ را نیز لازم دارند. برای توسعه، سرور را با `APP_ENV=development` روی درگاه 3000 و سپس Vite را اجرا کنید. تولید به پراکسی HTTPS کنترل‌شده نیاز دارد. نخستین پروفایل وضعیت `PBX_CONFIGURED_UNVERIFIED` می‌گیرد. شبکهٔ PBX تا زمانی که `APP_PBX_NETWORK_MODE=plain_tcp` صریحاً تنظیم نشود غیرفعال است. در این حالت، هر پروفایل فعال یک چرخهٔ اتصال پایدار با reconnect/backoff، رویدادهای زندهٔ نرمال‌شدهٔ AMI، Snapshot اولیهٔ `CoreShowChannels` در صورت دسترس‌بودن و Reconciliation دوره‌ای کانال‌ها دارد. شکست فقط در Snapshot، Provider را در حالت `DEGRADED` نگه می‌دارد و بدون reconnect روی بازهٔ عادی دوباره تلاش می‌کند. مدیر می‌تواند از دکمهٔ «آزمایش اتصال» یا `POST /api/pbx-instances/:id/test-connection` استفاده کند؛ موفقیت فرادادهٔ امن و زمان آخرین تأیید را ذخیره می‌کند. `GET /api/pbx-instances/:id/provider-status` وضعیت امن ارائه‌دهنده را برمی‌گرداند. شکست PBX یا آزمایش اتصال روی `/ready` اثر ندارد. AMI با TCP ساده فقط روی مسیر شبکه‌ای مورد اعتماد یا محافظت‌شده مناسب است.

پیش از اینکه یک PBX واقعی را Supported در نظر بگیریم، [Runbook تأیید سازگاری PBX واقعی](REAL_PBX_VERIFICATION.fa.md) را اجرا کنید. Verifier اختصاصی، Connection Input و نتیجهٔ Detailدار را فقط در `.local/` نگه می‌دارد و هیچ Call-Control Action ارسال نمی‌کند.
