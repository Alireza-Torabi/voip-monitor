# عملیات

**وضعیت:** سرور و رابط توسعهٔ محلی اجرا می‌شوند، پایگاه دادهٔ SQLite و نگهداری رمزگذاری‌شدهٔ اطلاعات محرمانه وجود دارند، اما هنوز سرویس پایش یا روش آزمایش‌شدهٔ پشتیبان‌گیری و بازیابی وجود ندارد.

بررسی‌های کنونی را از ریشهٔ مخزن اجرا کنید:

</div>

```sh
python3 scripts/check_foundation.py
python3 scripts/check_licenses.py
npm run lint
npm run typecheck
npm run test
npm run build
git status --short --branch
git check-ignore .local/DEPLOYMENT_CONTEXT.md
```

<div dir="rtl">

این بررسی‌ها وجود فایل‌های عمومی، الگوی محیطی بی‌خطر و نادیده‌گرفتن مسیرهای خصوصی را کنترل می‌کنند. جایگزین بازبینی دستی فایل‌های آمادهٔ ثبت در Git یا ابزار کامل کشف اطلاعات محرمانه نیستند.

پایگاه داده در مسیر تنظیم‌شدهٔ `APP_DATABASE_PATH` نگهداری می‌شود؛ مسیر پیش‌فرض کانتینر `/data/monitor.sqlite3` است. کلید اصلی در `<APP_SECRET_DIR>/master.key` جدا از پایگاه داده، در پوشهٔ مالک‌دار با مجوز 0700 و فایل با مجوز 0600 نگهداری می‌شود. کلید گمشده در حضور رکوردهای رمزگذاری‌شده دوباره ساخته نمی‌شود و شروع برنامه شکست می‌خورد. بازیابی آینده به پایگاه داده، کلید اصلی متناظر و پیکربندی زمان اجرا در صورت نیاز وابسته است. نسخهٔ پشتیبان باید پایگاه داده و فایل‌های جانبی مرتبط را به‌صورت سازگار و کلید اصلی را با کنترل دسترسی جداگانه در صورت امکان حفظ کند. پایگاه داده بدون کلید درست ممکن است اطلاعات محرمانه را برای همیشه غیرقابل‌بازیابی کند؛ کلید به‌تنهایی رکوردهای پایگاه داده را بازسازی نمی‌کند. راهنمای کامل استقرار، ارتقا، بازگشت نسخه و حذف نصب پس از ساخت سرویس نوشته خواهد شد.


رمزگذاری اطلاعات محرمانهٔ PBX با `AES-256-GCM` و نسخهٔ پاکت و کلید ۱ انجام می‌شود. هر بار از nonce تصادفی تازه استفاده می‌شود و دادهٔ احرازشده شناسهٔ PBX، نام اطلاعات محرمانه و هر دو نسخه را به متن رمزگذاری‌شده پیوند می‌دهد. متن آشکار هنگام استفاده کوتاه‌مدت در حافظهٔ سرور وجود دارد و JavaScript پاک‌سازی قطعی آن را تضمین نمی‌کند. چرخش کلید هنوز پیاده‌سازی نشده است.
</div>

<div dir="rtl">

در فاز ۲ وظیفهٔ ۴، برنامه فایل SQLite را در مسیر اعتبارسنجی‌شدهٔ `APP_DATABASE_PATH` می‌سازد و مهاجرت‌ها را پیش از شروع HTTP اجرا می‌کند. شکست پایگاه داده یا مهاجرت، شروع برنامه را متوقف می‌کند. `GET /health` زنده بودن فرایند را نشان می‌دهد؛ `GET /ready` آماده بودن پایگاه داده و فایل کلید متناظر را بررسی می‌کند و هنگام اختلال کد 503 می‌دهد. نبودن یا قطع بودن PBX روی آمادگی برنامه اثر ندارد. نسخهٔ پشتیبان آینده باید پایگاه داده و فایل‌های جانبی مرتبط را به‌صورت سازگار حفظ کند؛ دادهٔ محرمانهٔ رمزگذاری‌شده به کلید اصلی جداگانه نیز نیاز دارد. پشتیبان‌گیری، بازیابی و چرخش کلید هنوز پیاده‌سازی و آزمایش نشده‌اند.
