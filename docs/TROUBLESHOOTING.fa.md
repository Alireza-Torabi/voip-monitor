# رفع اشکال

**وضعیت:** برنامهٔ توسعه چرخهٔ اجرای ارائه‌دهنده و آزمایش اتصال AMI دارد، اما پایش تولیدی هنوز کامل نیست.

- اگر `node` یا `npm` پیدا نمی‌شود، نسخهٔ تعیین‌شدهٔ Node.js 24 را از منبع معتبر نصب کنید. Docker برای این کار محلی لازم نیست و Compose هنوز سرویسی ندارد.
- اگر بررسی شالوده خطا می‌دهد، فایل گزارش‌شده را پیش از ثبت در Git اصلاح کنید.
- اگر فایل خصوصی توسط Git نادیده گرفته نمی‌شود، پیش از نوشتن اطلاعات محلی، `.gitignore` را اصلاح کنید.
- اگر ارسال به GitHub شکست خورد، خطا، نشانی remote و وضعیت احراز هویت را بررسی کنید. اطلاعات ورود را خودکار تغییر ندهید و ارسال اجباری انجام ندهید.
- اگر اطلاعات محرمانه وارد فایل‌های آمادهٔ ثبت یا تاریخچه شد، کار را متوقف کنید، وضعیت انتشار را بررسی کنید و اعتبارنامهٔ آسیب‌دیده را تغییر دهید. حذف در ثبت بعدی تاریخچه را پاک نمی‌کند.

رفع اشکال آزمایش اتصال در ادامه آمده است؛ راهنمای بازیابی پایگاه داده و داشبورد پس از تکمیل آن مؤلفه‌ها گسترش می‌یابد. تغییر پیکربندی PBX واقعی بدون طرح بررسی‌شده انجام نشود.

برای سرور، ابتدا `npm run build -w backend` و سپس `npm run start -w backend` را اجرا کنید و مسیر `GET /health` را روی نشانی محلی بررسی کنید. برای رابط، `npm run dev -w frontend` را اجرا کنید. اگر بسته‌ها ناسازگار شدند، `npm ci --ignore-scripts` را با بررسی معتبر گواهی TLS دوباره اجرا کنید.

- اگر راه‌اندازی مدیر نخست لازم است، توکن را فقط با دسترسی محلی مورد اعتماد از پوشهٔ اسرار بخوانید. توکن گم‌شده فقط پیش از وجود مدیر ساخته می‌شود. مجوزهای ناامن باعث توقف راه‌اندازی می‌شوند؛ مالکیت و مجوزها را بدون انتشار محتوا اصلاح کنید.
- پاسخ 403 در راه‌اندازی می‌تواند از توکن نامعتبر، Origin ناهم‌مبدأ (HTTPS در تولید و HTTP در توسعه/آزمایش) یا وجود مدیر باشد. تلاش‌های زیاد تا یک دقیقه پاسخ 429 می‌دهند. بازنشانی خودکار مدیر وجود ندارد.
- پاسخ 401 در ورود را با نام کاربری یکسان‌سازی‌شده و گذرواژه بررسی کنید؛ حساب غیرفعال نیز 401 می‌گیرد. پاسخ 403 در POST نشانهٔ مشکل Origin است. پاسخ 401 در `/auth/me` می‌تواند از نشست منقضی یا باطل‌شده باشد؛ دوباره وارد شوید. کوکی تولید به HTTPS نیاز دارد.

</div>

- اگر رابط راه‌اندازی در توسعه پروفایل‌ها را بارگذاری نمی‌کند، ابتدا سرور را با `APP_ENV=development` روی درگاه 3000 و سپس Vite را اجرا کنید. پراکسی، Origin مرورگر را حفظ می‌کند. در تولید، POST به HTTPS و Host کنترل‌شده نیاز دارد.
- پاسخ 401 از API پروفایل به معنای نبودن یا انقضای نشست مدیر است؛ دوباره وارد شوید. پاسخ 403 برای تغییرها به بررسی Origin مربوط است. پاسخ 400 به اعتبارسنجی فیلدها (مانند نشانی، درگاه، ارائه‌دهنده یا گذرواژهٔ خالی) مربوط است؛ مقدار ردشده گزارش نمی‌شود.

اگر «آزمایش اتصال» اعلام کرد شبکهٔ PBX غیرفعال است، پیش‌فرض امن را نگه دارید یا فقط روی مسیر مورد اعتماد/محافظت‌شده `APP_PBX_NETWORK_MODE=plain_tcp` را صریحاً فعال کنید. پاسخ 502 یعنی ارائه‌دهنده نتوانسته اتصال، احراز هویت یا کشف را کامل کند؛ پاسخ عمومی عمداً جزئیات خام DNS، سوکت، AMI و اطلاعات محرمانه را نشان نمی‌دهد. مسیر احرازشدهٔ `GET /api/pbx-instances/:id/provider-status` وضعیت امن اجرای ارائه‌دهنده را می‌دهد. خرابی PBX به معنی خرابی آمادگی برنامه نیست؛ `/ready` را جداگانه بررسی کنید. تغییر تنظیمات اتصال یا گذرواژه زمان تأیید ذخیره‌شده را پاک می‌کند.
